# DragonDrop

Телеграм-бот и мини-апп: кейсы и апгрейдер по игре «Steal a Brainrot». Баланс пополняется звёздами Telegram или брейнротами по заявке, брейнротов из инвентаря можно вывести по заявке.

## Что внутри

**Бот (@DragonDrop_Bot)**
- `/start` — баннер, приветствие и кнопки: «Играть в Telegram», «Играть на сайте» (вход по личной ссылке), «Новости», «Поддержка», «Ввести промокод».
- Кнопка меню «Играть» открывает мини-апп.
- Промокоды можно вводить прямо в чате.
- `/admin <код>` выдаёт права админа, из админки работает рассылка.
- Имя, описание (RU/UK/EN), команды, аватарка и кнопка меню ставятся сами при первом запуске.

**Мини-апп** (папка `web/`)
- 10 кейсов с рулеткой, шансы видны игрокам: FREE, Нуб 10, Про 25, Рыбный 65, DLC 200, Хэллоуин 250, Летний 350, Драгон 450, Грибной 750, Грифон 2000.
- Платный кейс можно открыть сразу x1 / x2 / x3 / x5, если хватает баланса (несколько рулеток, общий результат).
- Кейсы делятся на категории, которые создают админы (заголовок над группой кейсов).
- FREE кейс открывается раз в N часов, нужно подписаться на канал и отправить ссылку на бота в любой чат.
- Апгрейдер со шкалой шанса; игрок выбирает нужный шанс ползунком или кнопками 75% / 50% / 30% (недостижимые скрываются) — цель с ближайшим шансом подбирается сама. Шанс = ставка / цель × (100 − комиссия), не выше макс. шанса, и делится на «невезение» (по умолчанию 1.06: при макс. шансе 80% кнопка 75% остаётся и шанс на ней настоящий; у отдельного аккаунта основной админ может умножить его ещё в N раз). Игрок видит ровно тот шанс, с которым сервер крутит: если настройки или цены изменились, апгрейд не крутится, а показывается новый шанс.
- Ракета: игрок ставит монеты или брейнротов и запускает ракету, множитель растёт с 1,00x; «Забрать» до взрыва — получает ставку × множитель (на брейнротах: самого дорогого брейнрота на сумму выигрыша + остаток монетами), после взрыва ставка сгорает. Точка взрыва выпадает при старте одинаково для всех: долететь до x можно с шансом (1 − комиссия) / x. Сколько получит игрок, считает сервер по своим часам; если приложение перезагрузили, летящая ракета находится снова.
- Последние дропы онлайн, топ дроп за 24 часа, счётчик онлайна. При наведении мышки на дроп (на телефоне — по касанию) видно, откуда он: какой кейс или апгрейдер.
- Профиль: статистика и инвентарь с продажей предметов и кнопкой «Вывести».
- Кнопка «+» у баланса — пополнение:
  - **Звёзды** — счёт в Telegram Stars (XTR), монеты зачисляются сами после оплаты по курсу из настроек;
  - **Брейнроты** — игрок пишет ник в Roblox и выбирает из списка брейнротов, которых отдаст (поиск, количество до 99, до 20 разных), уходит заявка; админ видит их в заявке с суммой. Какие брейнроты есть в списке, решают админы: «Можно пополнять» у предмета (по умолчанию у всех);
  - промокод.
  - при пополнении звёздами или брейнротами можно вписать реферальный код (первый введённый остаётся за игроком навсегда, неверный код не даёт пополнить).
  - у кода может быть бонус +N% (ставит только основной админ): игрок с таким кодом получает на N% больше монет при пополнении (напр. ввёл код на 15% и за 100 получил 115).
- Вывод: игрок выбирает брейнротов из инвентаря и пишет ник, предметы уходят в заявку (при отказе возвращаются). Выводить можно только отмеченных брейнротов (по умолчанию Garama and Madundung, Cerberus, Capitano Moby, Burguro and Fryuro, Dragon Cannelloni); остальные игрок меняет на одного из них, остаток уходит на баланс.
- По каждой заявке бот присылает игроку подтверждение; ответы админа приходят в бот, игрок отвечает кнопкой «Ответить» или реплаем.
- Языки RU / UA / EN, 6 цветовых тем, фон с пузырьками.

**Админка** (вкладка «Админ», видна только админам)
- Пополнения и Выводы: заявки по категориям «Работает» / «Выполнено» / «Отклонено» (оплаты звёздами — в «Выполнено»), счётчик новых, переписка с игроком через бота, начислить монеты, выдать брейнрота, «Выполнено» / «Отклонить». Админам в бот приходят новые заявки и ответы игроков с кнопкой «Открыть заявку».
- Кейсы: цена, картинка, лут и шансы, отдача считается на лету, кнопка «Привести к 100%», новые кейсы, категории (название, порядок, какие кейсы входят).
- Предметы: цена, эмодзи или картинка (загрузка / ссылка), редкость, «Можно выводить», «Можно пополнять».
- Игроки: поиск, баланс (добавить / установить), выдача и удаление предметов, бан, права админа, сброс входа на сайте; основной админ ещё задаёт невезение аккаунта (шанс в апгрейдере у этого игрока ниже ещё в N раз, игрок видит свой настоящий шанс). У каждого брейнрота игрока видно, откуда он и когда: из какого кейса, с апгрейдера (шанс и ставка), выдал админ, пополнение или возврат с вывода (номер заявки открывает её).
- Рефералы: админы создают коды (код и для кого), включают/выключают и удаляют их; основной админ задаёт у кода бонус +N% к пополнению; у каждого кода видно, сколько игроков пришло и сколько они пополнили брейнротами и звёздами (только после того, как игрок вписал код), и список этих игроков. Код игрока виден в его карточке и в заявке. Основной админ может выключить учёт звёзд для всех кодов (Настройки).
- Промокоды: сумма, число активаций, срок действия.
- Настройки: канал для FREE кейса и проверка, что бот в нём админ; ссылки; кулдаун; комиссия и шансы апгрейдера, комиссия ракеты (до 90% — чем выше, тем реже выигрыш), ставки и макс. множитель ракеты (меняет только основной админ, остальные видят); невезение апгрейдера, курс звёзд (монет за 1 ⭐) и что видят обычные админы (обзор, пополнения брейнротами, пополнения звёздами, выводы, кейсы, предметы, игроки, промо, настройки, рассылка: выключенное пропадает у них в админке и в уведомлениях бота, сервер такие запросы не выполняет) — видит и меняет только основной админ; стартовый баланс; свой текст `/start`.
- Рассылка всем игрокам и общая статистика.

## Стек

Node.js 22, Express 5, grammY, PostgreSQL. Фронтенд — чистый JS, без сборки. Таблицы лежат в своей схеме базы (`dragondrop`) и с префиксом `bs_`, поэтому базу можно делить с другим проектом (например, Supabase или старым BrainrotSpin) — DragonDrop видит только свои данные.

## Переменные окружения

| Переменная | Что это |
|---|---|
| `DATABASE_URL` | строка подключения Postgres (обязательно) |
| `DB_SCHEMA` | необязательно: схема базы для таблиц (по умолчанию `dragondrop`; пусто или `public` — обычная схема) |
| `BOT_TOKEN` | токен бота от @BotFather |
| `ADMIN_CODE` | код для `/admin <код>` |
| `API_URL` | публичный адрес сервера (на Render берётся сам из `RENDER_EXTERNAL_URL`) |
| `WEB_URL` | адрес мини-аппа, если он на отдельном статическом сайте; иначе равен `API_URL` |
| `BOT_MODE` | `webhook` (прод, по умолчанию при наличии `API_URL`) или `polling` (локально) |
| `ADMIN_IDS` | необязательно: Telegram ID постоянных админов через запятую |
| `OWNER_IDS` / `OWNER_USERNAMES` | необязательно: главные админы (ID или @username). Всегда админы, их нельзя забанить или снять; в админке выглядят как обычный админ. Аккаунт, первым зашедший с указанным username, закрепляется по ID. Только они видят и меняют курс звёзд (если главный админ не задан — все админы) |

## Запуск локально

```bash
npm install
DATABASE_URL=postgres://... BOT_TOKEN=... BOT_MODE=polling npm start
```

Таблицы и стартовые кейсы создаются автоматически при первом запуске.

## Деплой на Render

`render.yaml` описывает два сервиса:
- `dragondrop-api` — бот и API (web service);
- `dragondrop` — мини-апп (static site, не засыпает).

Бесплатный web service на Render засыпает после 15 минут без запросов, первое открытие после сна занимает до минуты. Мини-апп в это время показывает экран загрузки.

## Тесты

## Экономика

`scripts/design-economy.mjs` генерирует `src/seed-data.json`: 136 брейнротов (цены из прайса от 01.10.2026) и шансы с отдачей 90% у платных кейсов. Seed применяется только к пустой базе, дальше всё меняется в админке.
